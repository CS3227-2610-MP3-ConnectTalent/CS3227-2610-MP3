# Final PR submission

## Trigger and inputs

Use when contributor closeout is ready for submission. Read the [process](../../../workflow/AgentProcess.md), completed issues, final branch/diff/commits, approved packet, final record and every dated summary. Use the canonical [PR template](../../../.github/pull_request_template.md); do not substitute a competing checklist.

## Bounded actions

1. Verify issue links/closure scope and that the PR targets develop under the process. Confirm proposal/deltas/design-or-omission/plan approval, completed tasks and actual checks, reviewer independence/findings/dispositions, distinct student acceptance, accepted canonical sync before complete archive or justified N/A, guides/reflections and every pre-PR summary.
2. Inspect final staged/committed diff against the approved scope, final archive/record/log links and verification revision. Resolve readiness gaps through the owning stage before submission. Keep Failed/Not run/Blocked/N/A checks, accepted conditions, remaining risks and rollback/deployment limits explicit; missing gates cannot be silently waived.
3. Complete required closeout edits/checks and save the final closeout commit before opening. Prepare a reviewable title/body from the template with Closes #N for each resolved issue, IDs, artifacts, actual runs, checks and decisions. Do not claim unknown issue/PR URLs, repository enforcement or deployment outcomes.
4. Open the PR only if the user authorized submission and a suitable mechanism is available. Check authorization immediately before the external mutation; respect an existing no-live-PR instruction. If unauthorized, unavailable or blocked, return the finished draft, target/base/head and exact readiness/access limits with PR opening pending. Do not install tooling or use unrelated credentials to force submission.
5. When authorized creation succeeds, report the actual tool-confirmed PR URL/number/base/head and outcome. PR opening is the final contributor action; report the evidence without adding post-opening contributor edits. Later requested fixes begin follow-up work with updated evidence/logs.

## Output and handoff

Return readiness assessment, title/body, final commits and evidence links, remaining limits, and either creation pending or the actual PR result. Handoff is to repository reviewers and the students; this skill cannot approve or review its own PR, merge it, deploy, or authorize release.

## Quality and evidence checks

Match every readiness claim to final evidence. Check issue closure syntax, final link destinations, base/head and review scope. Separate preparation, attempted creation, tool-confirmed PR-open, merge and release states.

## Stop conditions

Stop opening for missing approval/acceptance/independence, unresolved readiness gates, incorrect target/scope, explicit submission prohibition, unavailable mechanism or access denial. Preserve the concrete draft and report the exact block. Never claim external creation without tool evidence.
