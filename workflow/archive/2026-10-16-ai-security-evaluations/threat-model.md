This is an initial source audit and proposed verification map, not a penetration-test result. Source baseline: `2a56ba1`; existing AI packet belongs to John. Follow-up owner: Paul.

| ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## Assignment questions and evidence destinations

- Attack surfaces/injection types: matrix above and versioned corpus, including direct, indirect, role-spoofing, encoded/multilingual, split-payload, exfiltration and workflow/output attacks. No RAG, browser tool or resume-to-LLM path exists; those are exclusions, not tested protections for features we do not have.
- Implemented features/tests: existing canonical SEC/AID/AIS controls versus proposed guards; link each actual source/test/case/result after implementation. Mocked tests prove boundary handling, not live model obedience.
- Agent limits: no tools, database credentials, autonomous submission, hiring actions or retrieval. Record input/output/byte/token/deadline/retry/quota limits and evaluator call budgets separately.
- Approval/oversight protection: Applicant preview/adoption and separate submit; source-visible HR review and separate status action; development spec approval, independent review, separate human acceptance and release gates. Untrusted content/reports cannot grant any of these decisions.

Primary reference: [OWASP LLM01 Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/) informs the taxonomy and layered-control approach. Application-enforced authorization and scope limits are not a claim of general model resistance. Probabilistic quality, hosted configuration, provider reliability and full audit completeness remain distinct evidence questions.

## Proposed live dataset: ai-security-v1-live12

All cases use fictional notes/letters for a synthetic software role, without contact fields, resumes, database reads or real credentials. Attack markers are public synthetic strings. Each case is sent once with baseline prompt text and once with refined prompt text through the same hardened client; total completion cap is 24.
