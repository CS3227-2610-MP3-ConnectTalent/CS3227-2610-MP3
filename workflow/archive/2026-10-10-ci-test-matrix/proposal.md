## Intent, problem, and motivation

The app CI job runs lint, Next.js type generation, typechecking, unit tests and build. A separate Supabase workflow runs local pgTAP, but does not run the repository's race suites or Playwright tests. Vitest has no CI coverage configuration or published test result. Contributor documentation is stale about which checks run in CI. Formatting/complexity work from issue #51 remains separate and is not changed by this packet.

Extend CI so the current checks remain, local database and concurrency checks run on pull requests and pushes, critical browser journeys run on pull requests, and the full browser suite runs on a schedule. CI must use disposable local Supabase and Mailpit services with keys generated by that local stack. Unit results and coverage should be visible in the workflow summary and downloadable artifacts without granting a PR-comment bot broader token permissions.

## Goals, non-goals, and scope boundaries

- Goals:
  - Keep existing app CI checks and set explicit read-only repository permissions.
  - Pin the Supabase CLI to the version in the lockfile and gate local database lint errors plus pgTAP.
  - Add one ordered command for all five existing race scripts; execute them against a fresh local stack with local-only cleanup credentials.
  - Run a small set of critical Chromium journeys on pull requests and the complete E2E suite nightly/on demand against local Supabase and Mailpit.
  - Make CI fail if required local test credentials are missing, so credential-gated tests cannot silently skip.
  - Produce Vitest JUnit and coverage reports, a GitHub Actions job summary, and downloadable artifacts. Establish a coverage baseline without adding an unreviewed threshold.
  - Update contributor documentation to reflect triggers, check responsibilities and external branch-protection limits.
- Non-goals: Applicant/HR behavior, Supabase hosted projects, production data, product requirements, docs website, PR-comment bots, coverage thresholds, and the separate #51 formatting/complexity proposal.
- Users/roles: repository contributors and maintainers; no product user or role behavior changes.
- Scope boundaries: workflow YAML, package scripts/lockfile, Vitest and Playwright configuration, a small CI summary helper, and relevant CI instructions in README, CONTRIBUTING and Developer Guide. Do not inspect or modify personal reflection files. Preserve historical records and unrelated work on `chore/51-quality-gates`.

## Alternatives and dependencies

| Alternative | Benefit / cost / risk | Decision and reason |
| --- | --- | --- |
| Keep local database, race and browser suites out of CI | Lowest hosted runtime; leaves serious database and browser regressions to individual machines | Rejected; PR checks should exercise the isolated local stack. |
| Post coverage as a PR comment using a write-capable token | Summary appears directly in the conversation; adds token permissions and third-party comment action risk | Rejected; use Actions job summary and artifacts with read-only workflow permissions. |
| Run the entire E2E suite on every PR immediately | Maximum PR coverage; runtime and flakiness are not yet measured in CI | Deferred; run critical journeys on PRs and full suite nightly/on demand, then reassess from measured evidence. |
| Use hosted Supabase credentials in CI | Avoids local stack startup; risks tests touching shared or private data | Rejected; all database, integration and browser checks use fresh disposable local Supabase and generated local keys. |

- Assumptions: `supabase` CLI `2.119.0` matches the locked package version at intake; hosted GitHub Actions runners provide Docker and can start the configured local stack.
- Dependencies: issue #55; current `origin/develop` baseline; GitHub-hosted Actions and local Supabase CLI support.
- Risks: local stack runtime/resource use; E2E instability; keys may leak if printed; source changes can add skipped tests without breaking Playwright. Mitigations: separate jobs, one worker, local-only generated/masked keys, explicit key-presence guard, test reports/artifacts and nightly full E2E while runtime is measured.
- Open decisions: GitHub branch protection required-check configuration is outside the repository and remains to be confirmed by a repository administrator.
